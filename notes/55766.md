# vLLM #55766 vs the hybrid glass-box: status (2026-11-25)

## 1. Trigger (from the issue, its 3 comments and linked issues/PRs)
- Report: v0.28.0, Qwen3.8-27B BF16, TP2 H100, prefix caching (align, block 816), **ngram spec decode k=5**, chunked
  prefill mnbt 8192, default cudagraphs. A = N*816 + r tokens (r in {6,8}; 4/10 half), B = A + reply + ~2k tokens
  -> NaN logits from B's first step. Root cause not established in the body.
- JulianZJN (4x4090 sm_89, TP4, v0.28.0 and main 71fc70d3): reproduced r = **1 + num_speculative_tokens** only.
  Align mode splits prefill on the block grid, so the last prefill chunk is r tokens; when r == 1+k the step has the
  spec-verify decode shape and Model Runner V1's `_is_uniform_decode` (shape-only) dispatches it to the captured
  FULL decode cudagraph. The GDN metadata builder treats it as a prefill and does not refresh its persistent
  spec-decode buffers, so the graph replays the PREVIOUS spec step's state block ids / num_accepted_tokens: it writes
  GDN state into stale blocks (one reused as an attention KV block -> fp32 state read as bf16 KV -> NaN), and the
  current request's state is not written. The NaN block is full -> prefix-cached -> B (and retries) NaN.
  Needs: an earlier full-draft spec step (fresh server: stale buffers hold the null block -> state silently lost, #49918).
  Clean with cudagraph_mode=PIECEWISE, enforce_eager, or ngram off. Fixed by open PR #47123 (not merged).
- HassanHassnain: v0.32.0, RTX 3090, Qwen3.5-4B, MTP k=3, tail = 4 = k+1 -> 58/60 wrong state (37 NaN); **only with
  VLLM_USE_V2_MODEL_RUNNER=0**; V2 runner and eager clean.
- tingtu0721: Thor sm_110, 0.27.1, MTP k=1: k=2 (=1+k) fails, plus an unexplained k=10 case on the NEXT request; PIECEWISE fixes both.
- Related, all OPEN/unmerged: #49918, #53051 (bug reports of the same misdispatch), PRs #47123, #53059, #60512, #55123,
  #54076 (align chunk split), #55506 (spec block-table indexing). No merged fix for V1.
- vLLM 0.34.0 (our build): Model Runner V1 is removed. V2's `gather_batch_req_state` sets
  `decode_graph_eligible = not has_prefill` (except 1-token extensions), so a prompt chunk can never take the FULL
  decode graph. Same guard already present in the 0.30.1 build's V2 runner (vllm-lorafix).
- Version history (no merged fix for the V1 misdispatch itself): until #40704 (merged 2026-10-06, 819852df) the
  V2 runner did not support ngram, so ngram configs silently FELL BACK to V1 (the report's v0.28.0 ngram setup ran V1
  by default). MTP ran V2 by default in 0.32 (V1 only if forced). #63373 (2026-11-07, aac1b2a4) removed V1.
  0.30.1 (vllm-lorafix, c055c1e0, ~2026-10-01) is pre-#40704: ngram -> V1 by default.
- Real model block size on 0.34.0: 576 (same as ckpt_hybrid: 16 v-heads/2 kv-heads vs our 32/4, same ratio).
- => Expected: the bug does not exist on 0.34.0; pre-fix = 0.30.1 (vllm-lorafix) with VLLM_USE_V2_MODEL_RUNNER=0.
- Our earlier glass-box configs never hit the shape anyway: the ngram configs used k=3 with big mixed batches and no
  N*block + 4 prompts submitted alone.

## Verdict (so far)
- Trigger: hybrid GDN model + spec decode (ngram or MTP, any k) + FULL cudagraphs (default FULL_AND_PIECEWISE) +
  Model Runner V1 + a prefill chunk of exactly 1+k tokens alone in its step (align-mode prefix caching makes the last
  chunk of an N*block + r prompt exactly r tokens, so r = 1+k). Prefix caching only carries the damage to later hits.
  "4-10 tokens past a boundary" in the title = r=6 for k=5; r=4/8/10 not reproduced by anyone (incl. here).
- Why the glass-box "passed" before: (1) it ran on 0.34.0, where the mechanism cannot occur (V1 removed by #63373;
  the V2 runner keeps prefill rows out of FULL decode graphs: decode_graph_eligible); (2) no earlier config had the
  shape anyway (boundary prompts never ran with spec decode; ngram runs used k=3 in big mixed batches).
- On the pre-fix build the UNCHANGED ckpt_hybrid catches it, directly (A) and via the cache (B), with the same r-
  selectivity and the same NaN symptom as the real model. No construction change was needed; harness changes only:
  sequential submission (--sequential 1) and boundary/A->B prompts sized to the engine's block (544 on 0.30.1,
  576 on 0.34.0) with r = 1+k.
- gb_034_ngram5_ab (0.34.0, r=6, N=1..3): **A 3/3, B 3/3 exact** (B hits 576/1152/1728), min 39.75.

  ngram exercises the same runner dispatch, but MTP drafter state (#53912, #55506) is not exercised.

  unexplained by anyone; not reproduced here (real model r=8 clean, 0/3).
- The glass-box NaN mechanism itself was not traced (its state entries are 0/1, which reinterpret as finite bf16; the
  NaN probably comes from reading never-written/foreign block memory as state). Detection does not depend on it:
  the MISS mode (own state lost) is caught at margin 40-80 without any NaN.
